# 캐노니컬 절차 — 5화 이상 대본 시 시놉시스 생성

## 트리거

잠금 또는 소유자 확인을 받은 대본이 **5화 이상**이면, HIL 1 정합 패키지를 생성하거나 갱신한다.

- 최초 생성: 다섯 번째 대본이 잠길 때
- 정기 갱신: 이후 5화 단위가 추가로 잠길 때
- 즉시 갱신: 기존 잠금 대본을 재개방·교체했거나, 주인공/식당 규칙/아크 결말에 영향을 주는 소유자 지시가 생겼을 때

## 입력 우선순위

1. 잠금 대본과 잠금 레지스터의 파일명·SHA-256
2. 소유자 제공 핵심 설정
3. 지정 구글 드라이브의 시각 코퍼스

글콘티·소설 메모·시장 소재표는 별도 승인 없이는 서사 사실의 입력이 아니다. 잠금본과 충돌하면 잠금본을 우선하고, 충돌 자체를 `보류`로 남긴다.

## 생성물

패키지에는 최소 다음 여섯 파일을 둔다.

1. `synopsis.md` — 한 문단 서사 요약, 현재까지의 흐름, 미확정 경계
2. `character_sheet.md` — 화면상 확정 / 비공개 핵심 설정 / 관계 / 연기 방향 / 룩 참조 분리
3. `arc_map.md` — 회차 범위, 화면 사건, 독자 소비 정서, 아크 끝 변화
4. `look_core.md` — 드라이브 원본 링크·선택안·사용 제한
5. `source_lock.md` — 입력 대본 목록과 해시
6. `README.md` — 상태와 승격 범위

## 작성 규칙

- 원고는 읽기 전용이다. 시놉시스를 맞춘다는 이유로 잠금 대본을 수정하지 않는다.
- 아크는 `현대적 역할 → 숨긴 결핍 → 한 끼 → 변화`로 적는다. 사건 줄거리만 늘어놓지 않는다.
- 화면상 확정, 소유자 제공 비공개 설정, 다음 화 후보를 반드시 분리한다.
- 10화 이후와 잠금본에 없는 게스트는 빈 슬롯으로 남긴다. “그럴듯한 다음 아크”를 캐노니컬 사실로 채우지 않는다.
- 룩코어는 지정 드라이브의 실제 에셋 ID/링크를 붙인다. 이미지 파일명만으로 서사를 추가하지 않는다.

## 검증과 상태 전환

1. 대본 수가 5 이상인지 확인한다.
2. 모든 입력 파일의 SHA-256이 `source_lock.md`와 일치하는지 확인한다.
3. 대본 파일의 변경 목록이 0인지 확인한다.
4. 충돌·추정·미확정 항목을 남기지 않고 확정 문장으로 쓰지 않았는지 확인한다.
5. 위를 통과해도 상태는 `candidate / owner_review_required`다. 소유자 승인 전에는 기존 승인 HIL, 외부 소개문, 제작 기준을 자동으로 바꾸지 않는다.

## 재개방 규칙

잠금 대본을 고쳐야 하면 기존 파일을 덮어쓰지 않는다. 새 버전과 새 해시를 만들고, 그 시점의 정합 패키지를 새로 생성한다. 기존 패키지는 이력으로 보존한다.
